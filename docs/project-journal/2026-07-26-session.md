## Product goal

Build a local-first AI Content Intelligence & Production Platform for finding
theory-worthy or scene-explanation moments in long entertainment videos and
turning selected moments into an editable vertical rough cut.

The immediate product is a single-user, native Windows Pre-Alpha. The broader
multi-user/cloud plan remains the future Alpha vision.

## Fixed Pre-Alpha decisions

- Native Windows 11; no WSL2, Linux or Docker requirement.
- Python 3.12 and Django 5.2.
- Server-rendered templates with small dependency-free JavaScript.
- SQLite in WAL mode.
- One sequential database-backed worker.
- Localhost access only at `127.0.0.1`.
- English UI and English source analysis.
- One local user; no login screen.
- Local AI is the active route; cloud providers are disabled interfaces only.
- Theory/scene explanation is the first optimized content mode.
- Adaptive 20/30/40 moment candidates based on source duration.
- Optional focus prompt; prompt re-ranking must not repeat media analysis.
- AI proposes a rough cut and the user remains in control of edits.
- Default target: 45 seconds, configurable from 30–60 seconds.
- Optional basic English captions.
- Preview target: 720×1280 H.264/AAC with blurred background and normalized
  original audio.
- Source maximum: 180 minutes or 20 GB.

## Static asset incident and resolution

The first Waitress launch rendered raw HTML because CSS and JavaScript returned
404. Waitress did not serve Django static files automatically.

The local-only URL configuration now exposes only the project `static`
directory under `/static/`. A regression test covers the CSS and JavaScript
responses.

Important operational lesson:

- Do not launch `start-app.ps1`, `start-app.cmd`, Waitress or another
  persistent process through a Codex shell tool. The background child can keep
  the tool command waiting indefinitely.
- Automated verification should use Django's test client.
- The user may start/stop the app by double-clicking:
  `scripts/windows/start-app.cmd`
  `scripts/windows/stop-app.cmd`

## Current integrity guarantees

- `AnalysisRun.clean()` rejects a SourceAsset belonging to another Project.
- `studio.services.create_analysis_run()` calls `full_clean()` before saving.
- Demo seeding uses that trusted creation service.
- Demo AnalysisRun and all demo HotMoment rows are created in one atomic
  transaction.
- Partial demo-seeding failure rolls back all rows.
- Moment selection summaries are recomputed from persisted database state.
- JSON responses return authoritative selected/rejected counts and duration.
- Displayed duration percentage is clamped to 0–100.
