# 1. Product Vision

Build a cloud-first web and mobile platform for entertainment-focused YouTube content creators.

The platform should help users:

1. Discover currently promising movies, series, episodes, characters, scenes, and content topics.
2. Select the YouTube channel and content concept for which the content will be produced.
3. Upload a user-provided long-form movie or series video.
4. Analyze the source video for:
   - Narrative importance
   - Emotional peaks
   - Music rises
   - Visual movement
   - Action
   - Character reactions
   - Dialogue
   - Story turning points
   - Theory potential
   - Short-form suitability
5. Extract approximately 20–40 strong candidate moments.
6. Present the moments as preview cards, usually around 30 seconds long.
7. Allow the user to select multiple moments.
8. Allow the user to describe the intended video using a natural-language prompt.
9. Generate an editable rough cut from the selected moments.
10. Generate multiple evidence-linked script alternatives.
11. Generate voice-over through providers such as ElevenLabs.
12. Edit the video through the platform's cloud editor.
13. Keep CapCut or external editors optional.
14. Estimate viral potential.
15. Provide probabilistic view forecasts.
16. Upload the final video to the selected YouTube channel as private or unlisted.
17. Require explicit authorized human approval before public publishing.
18. Learn from user decisions and post-publication analytics.

The system must support:

- Web application
- Mobile application
- Multiple users
- Multiple workspaces
- Multiple channels per workspace
- Multiple content concepts per channel
- Channel-specific AI behavior
- Channel-specific analytics and prediction calibration

# 2. Product Positioning

The product must not be positioned as a generic AI clipping tool.

Existing products already provide combinations of:

- Long-form video clipping
- Auto captions
- Vertical reframing
- Basic virality scoring
- Prompt-based editing
- General YouTube trend discovery
- Social publishing and scheduling

The intended positioning is:

> An entertainment content intelligence and production operating system that determines what content should be created, from which scenes, for which channel, with which narrative structure, and at what time.

The main competitive advantages should be:

- Entertainment Opportunity Radar
- Narrative-aware moment detection
- Channel Brain
- Scene Genome
- Narrative Graph
- Human-directed story composition
- Evidence-linked scripts
- Theory Guard
- Cross-channel portfolio optimization
- Scene Reuse Guard
- Variant Arena
- Retention learning loop
- Probabilistic performance forecasting

# 3. Non-Negotiable Product Principles

## 3.1 Human-in-the-loop publishing

The platform must never publish a video publicly without explicit human approval.

AI may:

- Recommend topics
- Analyze videos
- Select candidate moments
- Generate rough cuts
- Generate scripts
- Generate voice-over
- Suggest edits
- Estimate performance

The user remains responsible for:

- Selecting the target channel
- Selecting the channel concept
- Selecting moments
- Approving the prompt
- Approving or editing the script
- Approving voice-over
- Approving the final render
- Approving public publication

## 3.2 User-provided media only

The platform must not include:

- Netflix downloaders
- HBO/Max downloaders
- Prime Video downloaders
- DRM bypass tools
- Screen recording protection bypasses
- Streaming platform credential storage
- Automated capture of protected streaming content

The user uploads the video file.

The platform should request a source-rights declaration, but the declaration must not be presented as legal clearance.

## 3.3 Cloud-first media workflow

The user should not need a permanent local project folder.

The platform should use:

- Direct browser-to-object-storage uploads
- Mobile upload support
- Temporary cloud storage
- Short-lived signed URLs
- Automatic media lifecycle deletion
- Cloud-based analysis
- Cloud-based preview rendering
- Cloud-based final rendering

## 3.4 Analyze once, reuse many times

A long source video should be deeply analyzed once.

The analysis should be reusable for:

- Multiple prompts
- Multiple rough cuts
- Multiple scripts
- Multiple channels
- Multiple channel concepts
- Multiple languages
- Multiple output formats
- Multiple future projects

## 3.5 Cost-aware AI model routing

The strongest and most expensive model must not be used for every task.

Recommended processing order:

1. FFmpeg and deterministic CPU analysis
2. Speech-to-text and audio signal processing
3. Lightweight embeddings and classifiers
4. Candidate filtering
5. Medium models for narrative and semantic analysis
6. Strong multimodal models only for top candidate scenes
7. Strong LLM only for final script reasoning and quality review

## 3.6 Evidence over hallucination

Every factual script statement should be linked to:

- A source timestamp
- A selected moment
- A transcript segment
- Or a verified external source

Each statement should be classified as:

- Confirmed by source
- Reasonable inference
- User interpretation
- Speculative theory

## 3.7 Provider independence

Domain logic must not depend directly on one provider.

Provider interfaces should exist for:

- LLM
- Vision model
- Speech-to-text
- Text-to-speech
- Object storage
- Trend data
- Video rendering
- Social publishing
- Analytics

# 6. Main User Workflow

## Stage 1 — Opportunity Radar

The user selects:

- Workspace
- YouTube channel
- Channel concept

The system recommends movies, series, episodes, characters, and content ideas with strong current potential.

Example:

```text
House of the Dragon — New Episode Opportunity

Episode age: 36 hours
Shorts view velocity: Very high
Competition: Medium-high
Content gap: Character theories and dragon scenes
Recommended publishing window: Next 12 hours
Opportunity score: 87/100
Recommended channel: Theory Channel
Recommended format: 38–48 second Short
```

The user may:

- Start a project
- Save the recommendation
- Dismiss it
- Request similar ideas
- Switch channel
- Switch concept

## Stage 2 — Project Creation

The project should contain:

- Selected channel
- Selected concept
- Movie or series title
- Season
- Episode
- Source language
- Target language
- Output format
- Target duration
- Content mode
- Spoiler level
- Theory level
- Rights declaration

## Stage 3 — Source Video Upload

Initial supported formats:

- MP4
- MKV
- MOV

Upload requirements:

- Direct upload to object storage
- Multipart or chunked upload
- Resume after network failure
- Upload progress
- File hash validation
- Duplicate detection
- Corruption detection
- Upload session expiration

The application server should not proxy the entire video file unless technically unavoidable.

## Stage 4 — Source Processing

The platform should generate:

- Low-resolution proxy
- Audio track
- Extracted embedded subtitles
- Automatic transcript
- Shot boundaries
- Scene boundaries
- Keyframes
- Audio intensity curve
- Music rise curve
- Dialogue segments
- Face or character clusters
- Motion features
- Narrative features
- Scene Genome
- Narrative Graph

## Stage 5 — Hot Moment Extraction

For a typical long movie or episode, return approximately 20–40 candidate moments.

Each moment card should contain:

- Preview start and end
- Recommended core range
- Scene summary
- Selection reasons
- Hot Moment score
- Spoiler level
- Characters
- Tags

Example:

```text
Moment 15

Preview:
00:46:21–00:46:51

Recommended core:
00:46:28–00:46:42

Reasons:
- Music rise
- High visual motion
- Main character close-up
- Strong short-form opening

Hot Moment Score: 92
Spoiler Level: Medium
```

Moment actions:

- Select
- Favorite
- Reject
- Find similar moments
- Show previous context
- Show following context
- Extend the moment
- Filter by character
- Filter by emotion
- Filter by action
- Filter by dialogue
- Filter by theory potential
- Filter by spoiler level

## Stage 6 — Moment Selection

The user may:

- Select multiple moments
- Reorder moments
- Lock a moment
- Add a note
- Replace a moment
- Ask AI to find a bridging moment

## Stage 7 — Prompt Studio

Example prompt:

Supported content modes:

- Logical Montage
- Theory
- Scene Explanation
- Character Arc
- Comparison
- Emotional Edit
- Episode Recap
- Hidden Detail
- Custom Prompt

Future quick-action buttons:

- Connect these scenes logically
- Turn this into a theory
- Strengthen the first two seconds
- Make it more dramatic
- Reduce spoilers
- Keep original audio
- Fit into 45 seconds
- Focus on a selected character
- Make the order chronological
- Convert to viral Shorts structure

# 18. Cost Optimization Strategy

1. Use signed multipart uploads directly to object storage.
2. Use proxy-first analysis.
3. Use sparse keyframes instead of processing every frame.
4. Use cascaded inference.
5. Cache by content hash and configuration version.
6. Deduplicate identical videos and artifacts.
7. Regenerate only changed TTS segments.
8. Re-render only affected timeline sections where practical.
9. Generate preview-quality variants before final rendering.
10. Use scale-to-zero workers where possible.
11. Record costs per workspace, channel, project, job, provider, model, TTS segment, render minute, and storage duration.

Recommended inference cascade:

```text
1. FFmpeg and deterministic CPU analysis
2. Transcript and audio feature extraction
3. Lightweight embeddings and classifiers
4. Candidate filtering
5. Strong multimodal analysis on top candidates
6. Strong LLM for final narrative and script review
```

# 25. Architecture Evolution

Start with:

> Modular monolith plus background workers.

Reasons:

- Lower operational complexity
- Lower infrastructure cost
- Faster development
- Easier local development
- Easier domain refactoring
- Easier testing

Keep clear module boundaries so the following may later become independent services:

- Video Analysis
- Rendering
- Trend Collection
- Prediction
- YouTube Integration

Extract services only when justified by:

- Independent scaling
- Failure isolation
- Different runtime requirements
- Security isolation
- Cost optimization
- Team ownership

# 32. Claude Code Implementation Guardrails

1. Do not implement unresolved architecture decisions without approval.
2. Do not add automatic public publishing.
3. Do not add DRM bypass or protected-stream downloading.
4. Do not hard-code one AI or TTS provider into domain logic.
5. Do not run long media jobs inside synchronous API handlers.
6. Do not expose OAuth tokens.
7. Do not expose unauthorized media URLs.
8. Do not skip workspace authorization.
9. Do not skip channel authorization.
10. Do not retain media beyond approved lifecycle rules.
11. Do not build advanced mobile editing before web validation.
12. Do not introduce microservices prematurely.
13. Do not claim deterministic view prediction.
14. Do not present AI-generated theories as confirmed facts.
15. Do not regenerate expensive valid cached artifacts.
16. Do not start coding before the current phase and acceptance criteria are approved.
17. Keep changes small, reviewable, tested, and documented.
18. Follow the project's Agent 1 procedure for planning, approval, file changes, terminal actions, testing, and reporting.
